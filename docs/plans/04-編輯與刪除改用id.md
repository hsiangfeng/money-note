# 編輯與刪除：改用 id 識別記錄（修正「刪錯筆」）

## Context

使用者回報：昨天午餐 120、今天飲料 60 兩筆，清單新到舊顯示為「飲料、午餐」；點「午餐」開編輯表單按刪除確認，消失的卻是「飲料」，且沒有任何錯誤訊息。

### 根本原因

**畫面清單的 index 被直接拿去當儲存陣列的 index 用，兩個陣列的順序不一樣。**

- `records`（`useRecords.js:30`）是 push 順序（存檔先後）：`[午餐, 飲料]`
- `monthRecords`（`useRecords.js:35-40`）是篩掉非本月、再依 `date` 新到舊排過的 computed：`[飲料, 午餐]`

事件路徑：

1. `RecordList.vue:22-26` 的 `v-for` 用的是 `monthRecords`，點列時 `emit('select', index)` 傳出的是**畫面上的第幾筆** → 點午餐 = `1`
2. `App.vue:27-29` 用這個 index 去 `monthRecords[1]` 取資料餵表單 → 表單顯示午餐（**這一段是對的，所以畫面看起來沒問題**）
3. `App.vue:57` 把同一個 index 交給 `deleteRecordAt(1)`
4. `useRecords.js:113-117` 拿 `1` 去 `records.value.splice(1, 1)` → `records[1]` 是飲料 → **刪掉飲料**

沒有錯誤訊息是因為 `if (!records.value[index]) return` 只擋「index 超出範圍」，不擋「index 對到別筆」；兩個陣列剛好都有 2 筆，index 1 在兩邊都合法。

同一個問題也存在於 `updateRecordAt`（`useRecords.js:102-110`）：點第一筆改金額，改到的會是另一筆。切到別的月份後更嚴重，因為 `monthRecords` 是篩過的，index 幾乎必定對不上。

### 這是刻意留的 bug

`docs/plans/03-編輯與刪除.md` 明寫「這次刻意留一個 bug……用陣列 index 當識別，作為後續的可控除錯練習」，程式裡所有相關位置都有 `// TODO 後面練習用：改成用 id`（`useRecords.js:100,112`、`App.vue:23,36,48,56`、`RecordList.vue:10`）。這次就是把它修掉。

---

## 修法：全線改用 `record.id`

`id` 在 `addRecord` 時就已經產生（`newId()`），每筆都有、不會重複，直接拿來當識別。

### 1. `src/composables/useRecords.js`

- `updateRecordAt(index, payload)` → `updateRecord(id, payload)`：`const index = records.value.findIndex((r) => r.id === id)`，`index === -1` 就 return，其餘邏輯不變（展開合併保留 `id`／`createdAt`，`save`）
- `deleteRecordAt(index)` → `deleteRecord(id)`：同樣 `findIndex` 後 `splice`，找不到就 return
- `useRecords()` 回傳改名後的兩個函式
- 移除三處 `TODO 後面練習用` 註解，改成說明「識別一律用 id，不用畫面 index（畫面清單是排過、篩過的，順序跟儲存陣列不同）」

### 2. `src/components/RecordList.vue`

- `@click="emit('select', record.id)"`
- 移除 `TODO` 註解與「傳出去的是畫面上的第幾筆」那句，`v-for` 不再需要 `index`

### 3. `src/App.vue`

- `editingIndex` → `editingId`（`null` = 新增模式）
- `editingRecord = computed(() => editingId.value === null ? null : (monthRecords.value.find((r) => r.id === editingId.value) ?? null))`
- `openEdit(id)`、`onSave` 改呼叫 `updateRecord(editingId.value, payload)`、`onDelete` 改呼叫 `deleteRecord(editingId.value)`
- 解構改成 `updateRecord`、`deleteRecord`；移除四處 `TODO` 註解

### 4. `docs/plans/04-編輯與刪除改用id.md`

依 CLAUDE.md，計畫放行後**第一件事**先把本計畫原文存進去，再動程式；跟程式碼同一個 commit。

`SPEC.md` 不動：這是修 bug、回到 SPEC 原意（每筆有 `id`），不是範圍或技術選型的改變，不需要在第 10 節補列。

## 驗收

`npm run dev`，DevTools 清掉 `money-note:records:v1` 從空狀態開始。

**使用者的重現步驟（主驗收）**

1. 新增昨天午餐 120 飲食 → 新增今天飲料 60 飲食
2. 清單顯示「飲料、午餐」
3. 點「午餐」→ 表單帶入 120／飲食／昨天 → 刪除 → 確認
4. **午餐消失、飲料還在**，總額 60、佔比飲食 100%

**plan 03 當初標「已知會錯」的案例**

- 同一天連記 100 / 200 / 300 三筆，分別點**第一筆**與**最後一筆**：編輯改金額後改到的就是點的那筆；刪除也是刪點的那筆
- 點中間那筆（原本剛好對）仍正常

**SPEC 第 7 節相關條目**

- 第 4 條：點一列改金額與分類，存檔後清單與統計同步
- 第 5 條：刪除先確認，確認後從清單與統計消失
- 第 6 條：重整後編輯／刪除結果還在
- 第 8 條：把某筆日期改成上個月 → 從本月消失、總額扣掉；切到上個月看得到那筆，並且**在上個月點它編輯／刪除也對到正確那筆**（跨月篩選後 index 必錯，id 才會對）

**邊界**

- 只剩一筆時刪掉 → 回到空狀態
- 編輯後 DevTools 看 localStorage，`id` 與 `createdAt` 沒變
