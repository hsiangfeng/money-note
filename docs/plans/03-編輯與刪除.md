# 編輯與刪除：點清單列開表單、表單內刪除

## Context

首頁的流水清單目前是唯讀的，點下去沒有任何反應。`docs/plans/01-新增一筆支出.md` 當初刻意把「點清單列開編輯表單」與「刪除」留給後面兩項，資料層也只寫了 `addRecord`，沒有 `updateRecord` / `deleteRecord`。

這次補上這兩件事，讓 SPEC 第 7 節的第 4、5、8 條驗收條件變成可驗：

- 第 4 條：點清單任一列可以修改金額／分類／日期／備註，存檔後清單與統計同步更新
- 第 5 條：刪除會先跳確認，確認後該筆從清單與統計中消失
- 第 8 條：把某筆的日期改成上個月，該筆會從本月消失

**這次刻意留一個 bug。** 使用者要求把「畫面列表上的第幾筆」（陣列 index）當成編輯與刪除的識別，不要用每筆記錄的 `id`，作為後續的可控除錯練習。所以下面所有設計都走 index，並在相關程式旁加註解 `// TODO 後面練習用：改成用 id`。**實作時不要順手改成 id。**

---

## 這個 bug 長什麼樣、什麼時候會炸

先講清楚，免得實作到一半覺得哪裡怪就自己修掉了。

`records`（原始陣列）是 push 順序；`monthRecords`（畫面清單）是「日期新到舊、同日再依 `createdAt` 新到舊」排過的。同一天記三筆 A→B→C 的話：

| 畫面 index | 畫面上是誰 | `records[index]` 是誰 |
|---|---|---|
| 0 | C（最新） | A（最舊） |
| 1 | B | B |
| 2 | A（最舊） | C（最新） |

`App.vue` 拿 index 去 `monthRecords` 撈資料餵表單（**顯示正確**），`useRecords.js` 拿同一個 index 去動 `records`（**寫入錯誤**）。於是：

- **點中間那一筆 → 剛好對**（反轉後中點不動），使用者給的驗收標準會完整通過
- **點第一筆 → 表單顯示 C，存檔／刪除卻打到 A**
- 跨月切換後更亂：`monthRecords` 是篩過的，index 幾乎必定對不上 `records`

這是真實世界最常見的寫法與最常見的 bug，刻意保留。

## 逐檔修改

### 1. `src/composables/useRecords.js`

新增兩個函式並 export（沿用既有的 `save(records.value)` 寫回慣例）：

```js
// TODO 後面練習用：改成用 id
// 這裡收的 index 是「畫面列表上的第幾筆」，不是這筆記錄的 id。
function updateRecordAt(index, { amount, category, date, note }) {
  const target = records.value[index]
  if (!target) return
  // 保留原 id 與 createdAt，只更新內容（SPEC 5.2「編輯時」）
  Object.assign(target, { amount, category, date, note })
  save(records.value)
}

// TODO 後面練習用：改成用 id
function deleteRecordAt(index) {
  records.value.splice(index, 1)
  save(records.value)
}
```

`useRecords()` 的回傳物件加上這兩個。`monthTotal` 與 `categoryStats` 都是從 `monthRecords` 推出來的 computed，改動 `records` 後統計會自己跟上，不用另外處理。

### 2. `src/components/RecordList.vue`

- `v-for="(record, index) in records"`，`defineEmits(['edit'])`
- 每列的內容包進 `<button type="button" class="flex w-full items-center gap-3 px-4 py-3.5 text-left">`，`@click="emit('edit', index)"`（用 button 而不是在 `<li>` 上掛 click，鍵盤與螢幕閱讀器才按得到）
- `<li>` 本身移除 padding／flex，只留 `:key="record.id"`
- 加一點按下的回饋：`active:bg-slate-50`
- 傳出去的是 index，旁邊補註解 `// TODO 後面練習用：改成用 id`

### 3. `src/components/RecordForm.vue`

**props / emits**

- 新增 `record: { type: Object, default: null }`
- emits 加 `delete`

**開啟時的帶值**（改寫既有的 `watch(() => props.open)`）

```js
const isEditing = ref(false)
const isConfirmingDelete = ref(false)

watch(() => props.open, async (open) => {
  if (!open) return
  const record = props.record
  isEditing.value = Boolean(record)
  isConfirmingDelete.value = false        // 每次開啟都收掉上次的確認狀態
  amount.value = record ? String(record.amount) : ''
  category.value = record?.category ?? ''
  date.value = record?.date ?? today()
  note.value = record?.note ?? ''
  await nextTick()
  amountInput.value?.focus()
})
```

`isEditing` 用元件內的 ref 而不是直接寫 `props.record ? '編輯' : '新增'`：關閉時 bottom sheet 有 0.25s 的滑出動畫，那期間 `props.record` 已經變成 `null`（刪除後更是變 `undefined`），直接讀 props 會讓標題在動畫中途閃回「新增」。

**標題**：`{{ isEditing ? '編輯' : '新增' }}`

**刪除區塊**（只在 `isEditing` 時出現，接在存檔按鈕下方）

- 未確認：一顆文字型的「刪除這筆」按鈕，`@click="isConfirmingDelete = true"`
- 已確認：就地換成一行「確定要刪除這筆嗎？」＋ `[取消]`（回到未確認）＋ `[刪除]`（`emit('delete')`），刪除鈕用紅色
- 都是 `type="button"`，不要被表單的 submit 吃掉

用就地確認而不是 `window.confirm()`：樣式可控、手機上不是系統對話框，也不會擋住之後用瀏覽器自動化實測。

### 4. `src/App.vue`

```js
const isFormOpen = ref(false)
const editingIndex = ref(null)   // TODO 後面練習用：改成用 id

const editingRecord = computed(() =>
  editingIndex.value === null ? null : monthRecords.value[editingIndex.value] ?? null,
)

function openAdd() {
  editingIndex.value = null
  isFormOpen.value = true
}

function openEdit(index) {
  editingIndex.value = index
  isFormOpen.value = true
}

function closeForm() {
  isFormOpen.value = false
  editingIndex.value = null
}

function onSave(payload) {
  if (editingIndex.value === null) addRecord(payload)
  else updateRecordAt(editingIndex.value, payload)
  closeForm()
}

function onDelete() {
  deleteRecordAt(editingIndex.value)
  closeForm()
}
```

- FAB 的 `@click` 改成 `openAdd`
- `<RecordList :records="monthRecords" @edit="openEdit" />`
- `<RecordForm :open="isFormOpen" :record="editingRecord" @save="onSave" @delete="onDelete" @close="closeForm" />`
- 從 `useRecords()` 多解構 `updateRecordAt`、`deleteRecordAt`

## 驗收

`npm run dev`，先清掉 localStorage 從乾淨狀態開始。

**使用者指定的主驗收**

1. 連續記三筆同一天的支出（例如 100 / 200 / 300）
2. 點清單**中間**那一筆 → 表單標題是「編輯」，金額／分類／日期／備註都帶入原值
3. 按「刪除這筆」→ 就地跳出「確定要刪除這筆嗎？」
4. 按「取消」→ 確認收起來，清單、總額、佔比全都沒變
5. 再按一次刪除 → 按「刪除」→ 表單關閉，清單只少中間那一筆，總額少 200，佔比同步更新

**SPEC 第 7 節相關條目**

- 第 4 條：點一列改金額與分類，存檔後清單與統計同步更新
- 第 5 條：刪除先跳確認，確認後從清單與統計消失
- 第 8 條：把某筆日期改成上個月 → 該筆從本月清單消失、總額扣掉
- 第 6 條：重整頁面，編輯／刪除的結果還在（確認有寫回 localStorage）

**邊界**

- 編輯模式把金額清空 → 存檔鈕禁用
- 只剩一筆時刪掉 → 回到空狀態，不是壞掉的空清單
- 表單開著時點遮罩關閉 → 再開新增，欄位是乾淨的、確認狀態沒殘留
- 編輯後 `id` 與 `createdAt` 沒變（DevTools 看 localStorage）

**已知會錯、這次刻意不修**：點清單第一筆或最後一筆，表單顯示的是對的那筆，存檔／刪除卻打到另一筆。
