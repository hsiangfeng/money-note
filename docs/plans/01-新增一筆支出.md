### 2. `src/composables/useRecords.js`（新增）

**全專案唯一碰 `localStorage` 的地方。** 用 module 層級的 `ref` 當單例 —— `useRecords()` 每次都回傳同一份 state，否則 `App.vue` 與之後的元件會各自持有一份、彼此不同步。

這次只寫用得到的：

| 導出 | 說明 |
|---|---|
| `records` | 全部記錄的 `ref`，初始化時從 localStorage 讀 |
| `monthKey` | `ref('YYYY-MM')`，初始化為當地時間的本月。**這次固定不變**，切換月份的函式留給第四項 |
| `monthRecords` | `computed`，篩出 `monthKey` 該月，並排好序 |
| `monthTotal` | `computed`，該月 `amount` 加總 |
| `addRecord(payload)` | 補上 `id` / `createdAt`，push 進 `records` 並寫回 localStorage |

三個地雷的對應寫法：

- **月份判定看 `date` 不看 `createdAt`**：`monthRecords` 的 filter 條件是 `r.date.slice(0, 7) === monthKey.value`。
- **不碰 UTC**：`date` 本身就是當地時間的 `YYYY-MM-DD` 字串，取月份**直接切字串**，不要繞去 `new Date(r.date)` —— 那會被當成 UTC 午夜解析，在台灣是前一天早上八點，跨月時會歸錯月。同理，「今天」與「本月」都用 `new Date()` 的 `getFullYear()` / `getMonth()` / `getDate()` 組出來，不用 `toISOString()`。
- **排序**：`b.date.localeCompare(a.date) || b.createdAt - a.createdAt`（日期新到舊，同日再依 `createdAt` 新到舊）。`filter` 已回傳新陣列，直接 `sort` 不會動到原始資料。

讀取的容錯（SPEC 第 4 節明文要求）：

```js
function load() {
  try {
    const parsed = JSON.parse(localStorage.getItem(STORAGE_KEY))
    return Array.isArray(parsed) ? parsed : []
  } catch {
    return []
  }
}
```

`JSON.parse(null)` 回傳 `null`、壞字串會 throw —— 兩種都要收斂成空陣列，所以 `Array.isArray` 與 `try/catch` 都不能省。

**一個實作細節要注意：`crypto.randomUUID()` 只在 secure context 可用。** CLAUDE.md 寫著手機實機測試用 `npm run dev -- --host`，那是 `http://192.168.x.x:5173`，非 secure context，`crypto.randomUUID` 會是 `undefined` —— 存檔會直接爆掉，而且只在手機上爆、桌機 localhost 完全正常。所以 id 產生要有 fallback：

```js
const newId = () =>
  crypto.randomUUID?.() ?? `${Date.now()}-${Math.random().toString(16).slice(2)}`
```

### 4. `src/components/RecordForm.vue`（新增，這次只做新增模式）

Bottom sheet，由下往上出現。`props: { open }`，`emits: ['save', 'close']`。表單狀態留在元件內，存檔時 emit 出去，**元件不碰 localStorage**。

照 SPEC 第 5.2 節：

| 欄位 | 實作 |
|---|---|
| 金額 | `<input type="text" inputmode="numeric">`，開啟時自動聚焦 |
| 分類 | 六顆按鈕（不是 `<select>`），從 `CATEGORIES` 跑出來 |
| 日期 | `<input type="date">`，預設今天（當地時間） |
| 備註 | `<input maxlength="50">`，選填 |

幾個決定：

- **金額用 `type="text"` + `inputmode="numeric"`，不用 `type="number"`。** 兩者在手機上都會跳數字鍵盤，但 `type="number"` 允許輸入 `-`、`.`、`e`，而規格要的是正整數；用 text 搭配輸入時過濾非數字字元，擋得比較乾淨，也沒有桌機的上下箭頭。
- **存檔按鈕的禁用條件是「金額不是正整數」或「未選分類」。** SPEC 只寫了金額那半句，但分類是必填且無預設 —— 不一起擋的話會存進 `category: null`。這是補洞不是加需求。
- 開啟時重置所有欄位（watch `open`），聚焦用 `nextTick` + template ref。
- 關閉方式：點遮罩、取消鈕。存檔後自動關閉。
- 面板底部加 `env(safe-area-inset-bottom)` 內距 —— `index.html` 已經是 `viewport-fit=cover`，不補的話 iPhone 的存檔按鈕會被 home indicator 壓到。

## 驗收標準

功能做完後手動走一遍。前半段是 SPEC 第 7 節可驗的部分，後半段是這次自己補的邊界檢查。

**對應 SPEC 第 7 節：**

1. **（第 1 條）** 開啟畫面 → 按右下角 `＋` → 游標已經在金額欄 → 輸入 `120` → 點「飲食」→ 按存檔。**三個動作內完成，中途沒有多餘的展開收合。**
2. **（第 2 條）** 存檔後表單自動關閉，該筆立刻出現在清單**最上方**，頂部本月總額同步增加 120。
3. **（第 6 條）** 重新整理頁面，剛才那筆還在，總額不變。
4. **（第 7 條，部分）** 清空 localStorage 後重整，顯示空狀態文案與新增提示，不是一片空白、也不是壞掉的清單。
   > 完整的第 7 條要能切到別的月份才驗得完，留到第四項。

**這次自己補的：**

5. 金額欄留空 → 存檔按鈕是禁用狀態；輸入 `0` → 仍然禁用；輸入 `1` → 才可按。
6. 未選分類時存檔按鈕禁用，選了才解鎖。
7. 金額欄輸入 `-5`、`12.5`、`abc` → 畫面上留不下這些字元，存進去的一定是正整數。
8. 備註打超過 50 字 → 打不進去。
9. 日期改成昨天存檔 → 清單依 `date` 排在今天那筆的下面（不是依存檔時間排在最上面），且 `MM/DD` 顯示昨天。
10. **跨月邊界**：把日期改成上個月的某天存檔 → 該筆**不出現在畫面上**（因為只顯示本月），本月總額也不變。這是預期行為，代表月份是看 `date` 篩的。
11. **時區**：DevTools 看 localStorage，`date` 欄位是當地時間的日期字串。若能在台灣時間凌晨 0 點～早上 8 點之間測一次最好 —— 用 UTC 的話這個時段會差一天。
12. **容錯**：DevTools 把 `money-note:records:v1` 的值手動改成 `not json` → 重整後畫面顯示空狀態，不是白畫面或 console 爆錯。
13. 手機實機（`npm run dev -- --host`）走一遍第 1 條 —— 這一步同時驗證數字鍵盤有跳出來，以及 `crypto.randomUUID` 的 fallback 有生效。
