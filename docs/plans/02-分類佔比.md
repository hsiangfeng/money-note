# 開發計畫：分類佔比

> 對應 [SPEC.md](../../SPEC.md) 第 5.1 節「分類佔比」，屬第 3 節「做」清單第 4 項的一部分。

## Context

首頁目前有本月總額與流水清單，但看不出來錢集中在哪個分類 —— 要自己掃過整份清單心算。SPEC 第 1 節說這個 app 的核心問題只有一個：「我的錢到底花去哪了」，總額只回答了「花多少」，沒回答「花在哪」。

這次補上 SPEC 第 5.1 節的**分類佔比橫條**，位置照示意圖放在總額下面、流水清單上面。純 CSS 橫條，不引任何圖表函式庫（SPEC 第 6 節與 CLAUDE.md 都明文禁止）。

同時也把 SPEC 第 7 節驗收條件第 3 條補齊 —— 那條要求「分類佔比條的長度與百分比正確反映該月各分類金額」，在沒有這個元件之前無法驗。

## 這次會做

### 1. `src/composables/useRecords.js`（新增一個 computed）

統計歸資料層，SPEC 第 6 節寫的就是「`useRecords.js` — 讀寫 localStorage、CRUD、月份篩選、**統計**」。元件只負責畫。

新增 `categoryStats`，從既有的 `monthRecords` / `monthTotal` 往下算，回傳已排序、已過濾、已算好百分比的陣列：

```js
[{ id: 'food', name: '飲食', amount: 200, percent: 67 }, …]
```

規則對應四條驗收：

| 規則 | 實作 |
|---|---|
| 同分類金額加總 | 走訪 `monthRecords`，用 `Map` 依 `category` 累加 |
| 沒花到的分類不出現 | **從記錄反推分類，不是從 `CATEGORIES` 反推記錄** —— 該月沒出現過的 id 根本不會進 Map，自然不會有一排 0 |
| 金額大到小 | `b.amount - a.amount` |
| 百分比四捨五入到整數 | `Math.round(amount / monthTotal * 100)`，**不做任何湊成 100% 的補償** |
| 上個月不列入 | 直接吃 `monthRecords`，月份篩選已經在上游做掉了（看 `date` 不看 `createdAt`） |

兩個 SPEC 沒寫、但必須自己定的細節：

- **金額相同時的排序。** SPEC 只寫「依金額由大到小」，沒說平手怎麼辦，而驗收條件第 3 條正好是三個分類各 100 的三方平手 —— 不定規則的話順序會跟著記錄的輸入順序漂移，同一份資料重整前後可能換位。做法：平手時退回 `CATEGORIES` 的宣告順序（飲食、交通、日用、娛樂、醫療、其他），對不到的 id 排最後。這需要在 SPEC 第 10 節補一列決策紀錄。
- **`monthTotal` 為 0 時直接回傳空陣列**，避免除以 0 算出 `NaN`。金額規格是正整數，理論上有記錄就不會是 0，但這是一行的事。

分類顯示名稱沿用 `constants/categories.js` 既有的 `getCategoryName(id)` —— 它已經處理過「對不到 id 就回傳原字串」，不用另外寫一份。這也讓萬一有未知 id 的舊記錄時，該筆仍然算得進佔比、不會讓橫條加起來對不上總額。

`useRecords()` 的回傳多導出 `categoryStats`。**不動 localStorage、不動既有的 CRUD 與排序邏輯。**

### 2. `src/components/CategoryChart.vue`（新增）

檔名照 SPEC 第 6 節建議結構。`props: { stats }`，唯讀顯示，沿用 `RecordList.vue` 的模式（元件收 props、不自己呼叫 composable）。

版面照 SPEC 5.1 示意圖排成一行：

```
飲食  ████████████  $5,200  42%
```

- 分類名固定寬（兩字）、橫條 `flex-1`、金額與百分比右側 `tabular-nums`
- 橫條是一層 slate-100 的軌道 + 一層 `:style="{ width: … }"` 的填充，**寬度只能用 inline style**（Tailwind 無法產生動態百分比 class）
- 顏色維持現有單色調（slate 系），不替每個分類配色 —— 那要往 `CATEGORIES` 加欄位，而排序＋長度已經足夠表達「哪個多」
- **填充寬度給一個下限（約 2%）**：金額很小的分類（例如 5000 裡的 10 元）會四捨五入成 0%，寬度 0 的橫條看起來像壞掉。文字仍然照實顯示 0%，只有寬度補到看得見

以 375px 為基準，固定欄位加起來約 160px，橫條還有約 200px 可用。

### 3. `src/App.vue`（插入一段）

在 `<header>`（總額）與 `<main>` 的清單之間插入 `CategoryChart`。

空狀態邏輯**沿用現有的 `monthRecords.length` 判斷**，不另外開一組條件 —— 用 `<template v-if>` 把 CategoryChart 與 RecordList 包在一起，`v-else` 的空狀態文案原封不動。這樣「該月一筆都沒有 → 圖表與清單都不顯示」是同一個開關，不會出現只剩半張圖的狀態。

## 驗收標準

先清空 localStorage 再照下面建資料。前四條是使用者指定的，後面是邊界。

1. **（使用者第 1 條）** 本月記飲食 120、飲食 80、交通 100 → 畫面上**只有兩條**橫條，飲食 `$200` 在上、交通 `$100` 在下，飲食那條明顯比較長（67% vs 33%）
2. **（使用者第 2 條）** 上面那份資料裡，日用／娛樂／醫療／其他**完全不出現**，沒有一排 0
3. **（使用者第 3 條）** 改成飲食 100、交通 100、日用 100 → 三條顯示 33%、33%、33%（加起來 99%，正常），三條等長，順序是飲食 → 交通 → 日用
4. **（使用者第 4 條）** 再記一筆日期改成**上個月**的支出 → 本月的橫條與百分比完全不變
5. **（SPEC 第 7 節第 3 條）** 橫條長度與百分比互相吻合，且百分比與 `金額 ÷ 本月總額` 對得上
6. **（SPEC 第 7 節第 2 條）** 新記一筆存檔後，橫條**立即**更新（金額、百分比、排序都跟著動），不用重整
7. **（SPEC 第 7 節第 7 條，部分）** 該月一筆都沒有時，橫條區塊整個不顯示，只有空狀態文案 —— 不是留一塊空白或一條長度 0 的軌道
8. 只有一筆記錄時 → 一條橫條、100%、滿版寬度
9. **小數字不消失**：記飲食 5000、交通 10 → 交通顯示 0%，但橫條仍看得見一小截，不是完全空白的一列
10. 記一筆很大的金額（例如 1234567）→ 千分位正常、版面沒有被撐爆或換行
11. 重整頁面，橫條與百分比不變
12. 375px 寬（DevTools iPhone SE）下不橫向捲動；桌機上跟著 `max-w-md` 置中

## 實作後補記（2026-08-14）

以上為計畫原文。實作走驗收時發現一處要改，記在這裡供日後對照：

**橫條的版面從 flex 改成 grid。** 計畫寫的是「橫條 `flex-1`」，照著做出來每一列會各自分配空間 —— 金額字數越長，那一列的 `flex-1` 軌道就越短。實測 `$1,234,567` 那列軌道 240px、`$10` 那列 292px，兩條橫條畫在不同長度的底上，**不同分類之間的長度就不能互相比較**了，正好違背這個元件存在的理由（也過不了驗收第 5 條）。

改法：`<ul>` 設 `grid`、`<li>` 設 `display: contents`，四個欄寬因此由整張表共用，金額欄跟著最長的那筆一起撐開，所有軌道等長。修正後實測五列軌道都是 270.6px，填充長度與百分比完全吻合。
